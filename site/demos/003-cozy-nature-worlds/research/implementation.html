原型实现记录

研究始于 2026-10-05，原型收尾更新于 2026-10-06（Asia/Shanghai）。本文件解释阶段 A 的实际实现与边界。objectives.md规定目标，verification.md保存最终检查条件与结果，notes.md记录过程、错误与修正。

技术选择与目录职责

原创原型「一隅」采用 Three.js 桌面 WebGL 路线，以一个小空间验证创造→探索→保存。运行时采用固定的 Three.js 0.186.1，ES 模块、加载器和 MIT 许可随项目保存。七个 Kenney Nature Kit GLB 使用 CC0；出处、大小、哈希和原始许可见 素材清单。运行时统一材质配色、降低金属感，不改写原始模型文件。

模块 实际职责 数据边界
demo/world.js 确定性地形、初始散布、笔刷散布、河流中心线、世界验证与 JSON 往返 不依赖 DOM 或 Three.js；世界数据可独立检查
demo/scene.js 本地 GLB 加载、实例化植被、地形与河面、光照与雾、相机、拾取、渲染设置 GPU 对象、资源与动画时间属于运行时
demo/walk.js 河道对象可见性、落点检查、漫游出生点和方向位移 渲染与碰撞共用可见对象集合；纯规则可回归检查
demo/storage.js 版本化本地存档封装、时间戳验证、存取错误传递 先完整验证和序列化，再写入存储
demo/app.js DOM 工具、输入路由、模式切换、30 个撤销快照、本地存取、文件与文本导入导出 把动作转为世界变更，再更新画面与反馈
demo/index.html / styles.css 原创界面、工具状态、存档提示、探索入口、文件对话框和窄屏面板 保留当前工具、模式与操作说明
package.json / dev-server.mjs 无构建依赖的本地 HTTP 服务与 Node 原生测试入口 默认仅监听 127.0.0.1:8033，提供 demo/ 静态内容

世界与画面分离后，保存、撤销、导入和算法检查使用同一份数据；GPU 缓存、加载状态和鼠标状态不进入作品存档。浏览器不需要 CDN 加载运行时或模型。

地形、模型与编辑

world.js 以种子确定性生成地形和初始对象。对象保存唯一标识、类别、平面坐标、比例、旋转与变体，落地高度由 heightAt 计算。世界最多保存 2,000 个对象；散布按坡度、河道距离与同类间距筛选。scene.js 使用 InstancedMesh 按模型及网格部件合并重复对象。

树、草、花笔刷在射线拾取的地面散布；连续拖动每隔至少 90 毫秒尝试一次，擦除按笔刷范围移除对象。一个连续指针笔画只在第一次实际变更时写入一份编辑前快照。环境、名称和设置变化也进入撤销历史；历史上限为 30 份，保存与导出不携带历史。

编辑→探索→返回使用同一份世界。探索模式下左键拖动环顾，WASD／方向键连续移动；屏幕方向按钮支持按住和短点。Esc 返回布置，恢复进入前的创作相机。探索输入不会触发植物笔刷。

walk.js 排除河道遮住的对象后，把同一集合用于渲染和碰撞。树与岩石按平面圆形半径阻挡；草花不阻挡。漫游限定在岛内有效地面，眼高为地面加 1.7。出生点先检查偏好位置，再尝试 250 个螺旋点和全岛网格；找不到可用点时报告失败并保留编辑模式。斜向位移归一化，避免组合方向键让速度变快。这是轻量漫游规则，尚未提供通用物理、坡度限制或水深游泳行为。

路径河流与流水外观

world.js 的 riverCenterX 生成由种子与泉眼控制的参数化中心曲线。riverPath 从泉眼到 z=-30 固定采样 96 点；heightAt 使用同一曲线形成河谷，路径高度为地形高度加 0.06。移动泉眼会同时重算河谷与路径，不是从任意现有地形中搜索河道。

scene.js 将路径扩展成河面带，并在出口延伸到岛边。流水 Shader 以河面 UV、时间和流向产生条纹、水纹与岸边亮色。地形匹配检查和水纹运动检查分别执行。减少动态设置冻结水纹时间、关闭 OrbitControls 阻尼；本期没有植被风动画或音频。

晨光、暮色、薄雾三种预设调整背景、雾、半球光与太阳光。低质量模式采用 96 段地形细分、禁用阴影并将像素比限制为 1；标准模式采用 144 段细分与阴影，像素比上限 1.5；高质量上限 2。自动模式按 1280×720 的视口像素预算计算 0.75–1.5 范围的像素比上限，属于屏幕适配，不是根据实时帧率动态调节。单次浏览器检查中切换低质量后绘制调用从 29 降到 16；这不等同于跨设备性能结论。

阶段 A 没有水体积累积状态。 当前无法表达蓄水、盆地填满、溢流或筑坝守恒。Cozy Country 2.6 的积水与改流属于公开产品行为；其数值算法仍未知。本轮采用独立的路径流水方案，阶段 B 水深传播提案见 technical-research.md。

世界格式与本地存档

外部 JSON 导出是经过 validateWorld 验证的纯世界数据，version 为 1。serializeWorld 与 deserializeWorld 共用验证入口，导入先完成解析和验证，再替换当前作品。

世界字段 当前约束
seed / terrain 无符号 32 位种子；尺寸固定为 64，保存高度与河宽参数
objects 最多 2,000 项；唯一 id，tree/grass/flower/rock 类别，有限坐标、比例、旋转和变体
spring x 在 -12 至 12，z 在 -12 至 24
name / atmosphere 1–80 字符名称；morning、sunset、mist 环境枚举
reducedMotion / quality 布尔设置；auto、low、medium、high 质量枚举

原生文件导入拒绝大于 1 MiB 的文件；文本解析也限制最大 1,048,576 字符，并拒绝格式、版本、必需字段、对象数与数值边界错误。验证入口拒绝访问器和危险键，生成经过验证的独立世界副本。坏输入不会先清空当前世界。

localStorage 使用键 yiyu-world-v1，保存的是封装，而非直接写入纯世界：

{
  "format": "yiyu-save",
  "version": 1,
  "savedAt": "2026-10-06T00:00:00.000Z",
  "world": { "version": 1, "...": "经验证的世界数据" }
}

以上时间是格式示例。storage.js 验证 format、封装版本、必需字段、有效 ISO UTC 时间与 world，并限制存档文本长度。写入前完成验证与序列化；存储访问或配额错误交给界面报告，不自动清空旧存档。启动时尝试恢复，读取坏存档则展示新场景与明确反馈。

文件对话框可展示和复制导出 JSON，也提供 Blob 下载链接；导入支持粘贴文本和选择 JSON 文件。剪贴板受限时选中文本并提示 Ctrl+C。导入可撤销。最终浏览器检查已确认文本与真实文件往返；下载是否实际落盘未验证，不能把发起下载提示当作文件保存成功。

种子仅保证同一生成算法版本内可重复。手工对象的坐标与变换被完整保存；未来变更地形算法时应明确迁移或拒绝，不能只靠同一种子承诺旧地形永远一致。

实际验证对应

详细日期、浏览器条件、最终测试数量、截图和操作证据以 verification.md为准。这里保留实现与目标之间的对应，不把单台浏览器检查扩大为所有环境保证。

目标 已执行检查 结果与边界
G01 · 启动与固定本地依赖 本地服务、Three.js 与七个 GLB 加载；最终新浏览器标签页控制台 原型可运行；最终 warn/error 为空，依赖与许可保存在项目中
G02 · 自然画面与素材 实际浏览器画面检查；CC0 模型来源记录 场景已呈现，截图见验证报告；不以原作宣传截图代替本原型证据
G03 · 笔刷、擦除与撤销 树增加 4、草增加 18、花增加 13；擦除与撤销恢复 三类笔刷及范围删除可用；每笔一次快照，上限 30
G04 · 泉眼与路径流水 水源换位；路径合法性与匹配地形检查；水纹时间检查 路径及河谷一起重排；不含积水或水量守恒
G05 · 创作探索循环 安全出生点、连续向前点按、拖动环顾、Esc 返回 相机从 [6.64,6.19,10.33] 移至 [6.46,5.95,8.54]，返回 [32,38,49]；世界签名保持不变
G06 · 本地保存恢复 保存、修改后恢复、刷新恢复；存储异常回归检查 浏览器保存世界签名 fdd7409a，刷新恢复一致；配额与访问异常以模拟适配器检查
G07 · JSON 往返与坏输入 对话框展示 158,421 字符、745 对象；粘贴与真实文件导入；version 99 拒绝 导入恢复 fdd7409a，坏输入保留当前世界；下载文件落盘尚未验证
G08 · 环境、减少动态与运行 三环境、低质量切换、动态冻结、控制台复查；390×844 窄屏检查 水纹时间 92.447→92.447；单次绘制调用 29→16；窄屏无横向溢出，未在真实手机上验证手势与性能

最终 npm test 为 16 项通过。测试覆盖世界确定性、散布边界、路径合法性、纯 JSON 往返、存储异常、坏存档拒绝、漫游可见性／碰撞／出生点与位移方向。浏览器下载事件复查仍超时，已保留文本复制和文件导入路径，没有将其计作落盘成功。实际用户假设 H01–H04 尚未检验，按 prototype-plan.md另行招募与观察。

扩展计划与文档网页关联

2026-10-06 将扩展计划接入演示。demo/index.html 顶部新增“扩展计划”，使用新标签页保留正在编辑的场景。build-research.mjs 从十份项目 Markdown 生成 demo/research/ 下的静态 HTML、原文副本与被引用的画面证据；本地文档链接改写为对应 HTML，保留章节锚点。页面提供关联文档导航、本页目录和返回演示入口，网页不依赖运行时 Markdown 库或外部 CDN。

文档构建采用本地固定的 Marked 18.1.0；来源与 MIT 许可见 构建依赖。构建时转义原始 HTML、检查本地引用，拒绝不支持的协议。npm run dev 前自动生成文档，build:research 手动同步，check:research 检查派生产物是否过期。构建过程不会修改原始文档。

总目录工具按静态文件中是否存在 research/expansion-plan.html 自动增加入口，不限定项目编号。既有 demo 文件复制机制同时携带文档页，链接采用相对路径以支持本地服务和 Pages 子目录。Pages 工作流构建后再同步总目录，提交检查验证正文与网页一致；本轮未执行线上发布。
