# 审查一次明确范围的代码变更

这是本研究页编写的学习示例，需根据项目和 Claude Code 版本适配。

## 目标与输入

先取得用户明确的修改范围：当前未提交修改、某个提交、给定分支比较或 PR。
如果范围不清楚，先澄清；不要自行假设比较基线。

读取相关项目规则，确认源码、测试、构建和其他检查的实际入口。

## 工作要求

1. 用当前可用工具取得对应差异、相关源码与必要上下文。
2. 说明行为变化，检查接口使用者、边界条件与相关测试。
3. 对每个疑似问题复查实际代码，给出位置、触发条件和影响。
4. 根据项目已有命令与当前授权执行必要检查；缺少环境或权限时记录原因。
5. 本次任务的意图是审查和报告。需要修改、提交或对外操作时，按用户实际授权处理。

## 输出

- 修改范围与行为变化。
- 具体发现：文件位置、触发条件、影响和证据；没有确认的问题时明确说明。
- 验证记录：实际执行的命令、结果和覆盖范围。
- 未验证项：环境、权限、依赖、数据或其他原因。
- 建议的下一步：针对具体发现或证据缺口。

## 验收

产出应对应本次范围，发现可复查，检查记录完整，已验证与尚未验证的结论分开。
角色、步骤和文字意图不替代运行时的工具权限或检查机制。
