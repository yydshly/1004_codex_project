核心问题

水本身，
能不能很好玩？

短视频吸引我们的是水景的生命感。接下来的研究，把这种观赏性变成玩家可以影响的过程。

  1. 操作能改变结果选路与拨水改变轨迹，放水时机决定救援。
  2. 变化能被看懂水先变化，鸭子随后响应。
  3. 下一圈值得再玩回流补池，再决定何时放水。

当前检验的是简单水流规则和视觉反馈。V4 以有限水量和浅湾门槛近似输运；V1–V3 使用速度场、路线约束与涟漪推力。完整流体模拟与长期可玩性仍待研究。

01 / 机制

把循环拆开，才知道哪里值得扩展

下面拆解 V2 / V3 的引流循环；V4 把同一思路变成上池蓄水、浅湾救援、下池收水与可见回流，让水量和时间参与判断。

→ → → → 回到上游

上游蓄水

V2 / V3 用命中后的四滴水触发升级。V4 将总水量限制为 120：初始上池 24、下池 96；水经可见回流管返回上池，池容量为 60，继续等待可能产生溢流。

V4：水量已参与规则，策略效果待验证
玩家操作

预判 + 补救

闸门决定主要路线，拨水调整局部偏移。要检验的是：玩家能否主动规划，而不只是追着亮圈点击。

水与鸭子

让力变得可读

流线、泡沫、鸭子的转向和惯性，应表达同一套运动关系。涟漪从点击处向外推，点在鸭子右边会把它推向左边。

视觉回程

让重来有理由

鸭子落水、游向回程水道，再被气泡抬回上游。回程本身也应值得观看，并逐渐成为玩家可以设计的一段水路。

02 / 玩法方向

把水变成选择，有三条值得验证的路

共同目标是让鸭子的行动来自玩家对水的改变。三条路线分别检验反应与补救、资源与时机、设计与试错。

已有基础挑战

引流入圈

在分流前选路，偏移时用涟漪补救。玩家需要读懂目标、时机和推动方向。

水与鸭子
水路决定主方向，局部推力调整轨迹。
可见循环
入圈 → 落水 → 气泡抬升 → 再次选路。
主要风险
如果只需追着左右提示开闸，熟悉之后缺少新的判断。
最小实验
保持规则与水速不变，比较方向提示开启、关闭时的预测和解释。
可试玩 V4

蓄水批量救援

先放 24 水争取及时首救，还是蓄到 48 集中放水争取连救？六只鸭在浅湾等待，湾内水量达到门槛才前进。

水与鸭子
浅湾水量至少 12 才输运鸭子；定量放水自动关闸，提前关闸后余水仍可能推动救援。
可见循环
上池 → 浅湾 → 安全池；下池水经回流管补池，已救鸭回到上游安全区，本轮不再计数。
主要风险
等待占用 45 秒救援窗；满池溢流绕过浅湾。及时首救、连救与余时奖励已加入，是否平衡仍需实际比较。
最小实验
比较小量多次与集中放水，记录首救时间、等待、放水量、溢流和救援次数，检验是否存在不同有效策略。
待实现

搭建完整循环

先摆三块挡板，再观察鸭子是否能通过目标并返回。让回程也成为玩家设计的一部分。

水与鸭子
挡板改变连通关系；断路会积水或停鸭。
可见循环
试运行 → 找滞留点 → 改水路 → 完整持续回游。
主要风险
只有唯一解会削弱创造性，过多零件会让因果难以读懂。
最小实验
固定水源与目标，用三块挡板检验是否存在两种有效设计。
先后顺序的理由

先确认玩家看得懂水，再把水量变成有代价的选择，最后开放搭水路。每次只加一条关键规则，才能判断乐趣来自哪里。

V1 / 自由玩水

先看反馈有没有趣

调水流、放鸭子、产生涟漪；探索瀑布、漩涡与分流。已经能观察变化，但目标和取舍较弱。

V2 / 循环挑战

把反馈接到目标上

开闸、入圈、蓄水、升级，加入可见回游。已验证一轮四次命中能够正常升级；这不等于已经验证玩家会持续想玩。

V3 / 可读水流

让因果能被解释

给出方向、分流时机、涟漪范围与具体失败原因。已经形成可试玩版本；是否减少误解，需要用实际记录检验。

V4 / 蓄水救援

让等待与放水有代价

把水量、浅湾门槛、溢流和救援时间接进循环，用及时首救与成批连救提供不同收益。每只鸭本轮只计一次，回到安全区后等待新一轮。奖励是否平衡、策略是否有趣，仍需实际试玩检验。

V4 程序检查：两种节奏都能完成回游

小放争取到了及时首救；集中放水更快救齐。程序轮询和帧率会影响时间，分数不能证明玩法平衡。累计放水可超过 120 格，因为同一批水会循环复用；四仓总量仍为 120 格。模型另行检查了守恒、浅水停鸭、暂停、溢流与收尾。

已经确认

  • 闸门改变主要分流路线；涟漪推力会影响鸭子移动。
  • 小鸭沿落水、游动、水柱、上游水道完成回游。
  • 命中水圈后的水滴可回到蓄水池，四滴触发升级。
  • 原型提供暂停、失败和重玩；窄屏控件能够换行。
原型运行与交互检查

还没有确认

  • 新玩家是否能及时读懂目标，以及涟漪的推动方向。
  • 失败主要来自误解、反应时间，还是操作精度。
  • 增加速度和鸭子数量，是否增加乐趣而非只增加压力。
  • 放水奖励是否平衡，以及自由搭水路是否会产生多种有效解法。

无需姓名；记录不会上传。

判断依据

  • 先记操作前的预测，再看结果；不要把“更快”直接当成“更有趣”。
  • V4 写明首救时间、等待时长、放水次数与水量、溢流、救援数和分数；没有显示或测量的数值标记未知。
  • V4 的首救、连救奖励与输运速度仍可调整；单次高分不能证明某策略总是更好。
  • 少量记录只用于发现问题。程序检查和实际试玩分别标记；V3 可交换提示顺序或换试玩者复测。
