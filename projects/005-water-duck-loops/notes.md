## 实现梳理

1. 原帖只提供视频，作者主页链接的是像素鸭子编辑器。是否属于游戏未确认；不能由游戏式画面推断可玩版本。
2. 用户明确关注“水和鸭子，或基于水”的游戏和效果，随后要求可玩性、互动及可见循环。
3. 自由玩水片段提供三种速度场、水流强度、加鸭、涟漪与暂停。
4. 循环挑战片段将闸门、鸭子分流、水圈命中、水滴回流和四滴升级连在一起；小鸭经水潭、气泡水柱及上游水道继续下一圈。
5. 本轮把两份片段保留在 `prototype-sources/`，用 `scripts/prepare-prototypes.py` 转为独立静态页面；主研究页通过原型切换、机制阶段和扩展实验详情组织内容。

关键数据流为：输入 → gate / ripple impulse → duck position → checkpoint → returning drop → reservoir charge → level。回游与水滴沿可见路径移动，进度在普通浏览器的 localStorage 保存。V3 延续挑战规则，增加可读性提示和可手工记录的次数。

## 补全：可读水流 V3 与研究记录

2026-10-05 继续补全，增加 `experiments/loop-readable.fragment.html`。方向提示标出分流点、去程和回程，鼠标预览与点击后的虚线范围解释瞬间向外推的涟漪。关闭提示时隐藏新增的流向叠层与分流阶段建议；亮圈、原有目标和结果仍保留。关闭提示只比较辅助信息，不是完全无说明模式。

V3 明确区分两类失败：分流前未选对闸，或在正确水路内偏离圈边；经过分流后换闸只改变速度，不能跨水路。最近结果、入圈、错路、偏圈与拨水次数可照抄到实验记录。重新开始清空当前挑战与计数，原 V2 进度使用另一份本地存储。

V3 阶段网页补充三条路线的决策、互动、循环、风险和最小实验：引流入圈、蓄水批量救援、搭建完整循环。当时只有引流挑战已有可玩版本；随后 V4 将蓄水路线做成独立原型，搭建完整循环仍待实现。

`demo/journal.js` 提供本地研究记录，包含假设、条件、顺序、提前预测、结果、解释与下一步；区分自己的试玩、观察他人、程序检查。JSON 导出保留全部条目及撤回标记，撤回记录可恢复。界面不自动将少量记录汇总为可玩性结论。

记录每页显示 20 条，旧记录不因分页而丢弃；写入失败时保留输入和已有记录。首次 V3 程序检查已实际导出并归档到 `experiment-records/2026-10-05-v3-program-check.json`，用于复现功能结果。

建议对照：保持水速、轮次、鸭子数量和观察次数相近，交换提示开关顺序，记录预测与误推而不是只比较分数。逐个随机目标未锁定，因此两次不是完全相同的关卡，不应把成绩差异全部归因于提示。

## 补全：蓄水救援 V4

继续把实验 B 做成独立的水量与时机挑战。可编辑源为 `experiments/reservoir-rescue.fragment.html` 与 `experiments/reservoir-core.js`，由原型打包脚本生成 `demo/prototypes/reservoir/`。研究页默认展示 V4，V1–V3 保留并在选择时加载。

总水量 120 在上池、浅湾、下池与回流管之间转移；初始上池 24、下池 96，上池容量 60。下池水沿约 3.5 秒的可见回流管返回上池。玩家选择少量放水 24 或集中放水 48，达到所选水量自动关闸，也可提前关闭。浅湾水量至少 12 才输运鸭子，关闸后余水仍可推动；不足时鸭子停留。满池溢流绕过浅湾回下池，不产生救援收益。

救援窗为 45 秒，目标为将六只鸭送入安全池，每只鸭本轮只计一次。截止后停止操作与输运，已救鸭和水继续完成可见回程后结算；鸭子回到上游安全区后等待新一轮。前 5 秒首救奖励 30 分，2.5 秒内接续救援加 5 分，救齐后还有余时奖励。首救和连救奖励、流量与输运速度是实验参数；水量转移和门槛用规则近似，没有压力、碰撞或真实流体求解。

设计推断：少量放水可以提早行动，争取及时首救奖励，集中放水可能带来连救与更短完救用时；等待占用救援时间，满池后的溢流不能救鸭。加入这些收益和代价是为了避免“永远等满”成为唯一答案，是否达到目的、奖励是否平衡仍需比较策略并观察实际玩家，不能由参数设计直接当成已验证结论。

记录表新增 `reservoir-pulse`、`reservoir-batch` 和 `reservoir-other` 三种条件。选择实验 B 默认切到 V4 其他策略，可再选具体策略；C–F 仍显示待实现。旧记录与版本 1 结构保留，V4 的 `hits` 表示救援次数、`nudges` 表示放水次数。首救时间、等待时长、每次放水量、溢流、截止时滞留和解释写在观察中，没有测量的数值标记未知。对照应使用相同初始状态，交换策略顺序；程序检查仍与实际试玩分开。

记录在新版首次读取时复制到独立 v2 存储区，原 v1 存储保持不变，以避免旧页面的条件校验过滤并覆盖 V4 条目；导出结构仍为版本 1。旧页后续写入不自动合并，应刷新后统一使用新版。V4 本轮不跨刷新保存，研究记录会保存。V4 没有单独的失误计数，应把未救数量和原因写进观察。

V4 的单浅湾批量救援及连救奖励只构成实验 E 的起点，跨区域传播、中断与补救的完整连锁玩法尚未实现。V4 的实际程序和界面检查记录另见 `verification.md`。

## 复现与实验

- 自动操作原型完成四次入圈：60 分、零失误，蓄水依次达到 1/4、2/4、3/4，然后进入第二轮。该检查验证规则连通和升级，不作为人类玩家表现。
- 对话组件曾回传第一轮、三次失误、10 分的单次状态。它只是一个试玩记录，可能提示目标可读性或响应时间问题；不能推出总体难度、满意度或留存结论。
- 静态审查曾发现连续涟漪可能将鸭子推离左岸，已对推力与水道位置加边界；回流中的水滴也随进度保存。
- 暂停与拨水按钮、A/D 键、窄屏布局已有检查。网页整理版的最终检查另见 `verification.md`。

## 发现与判断

可确认：水流变化能反馈到小鸭轨迹，命中与失败能连接到进度，鸭子能完成可见回游。

待确认：玩家是否能在抵达前预测路线；涟漪向外推的规则是否直观；主要操作能否形成规划与补救的配合；增加水速和数量是否只提高压力。

下一步实验按“玩家操作 / 画面反馈 / 验证问题 / 最小改动 / 记录指标”组织：读得见的水流、蓄水与溢流、自己搭循环、不同鸭子、连锁救援、瀑布花园。A / B 已有 V3 / V4 原型，效果仍待验证；C–F 待实现。V4 使用有限水量的转移账目，不代表真实流体求解；自由地形、正式关卡、碰撞流体与养成系统尚未添加。
